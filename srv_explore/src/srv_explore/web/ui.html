srv-explore · агентный эксплорер сервера

Интерфейс, позволяющий агенту безопасно работать и собирать информацию на сервере. Рядом с данными, логами и сервисами.

Explore-агент живёт на удалённом сервере за MCP-интерфейсом: подключаешься к нему нативно по MCP из локального кодового агента и работаешь как со скиллом. Безопасность помимо промпта обеспечивает окружение — read-only песочница — и система плагинов для контролируемого доступа к системам (docker, web) и данным (БД, кеши, файлы).

Как подключиться

  1. Запроси доступ у администратора — отдай ему публичную часть своего SSH-ключа, получишь токен srvx_…. Ключа нет — сделай: 
    ssh-keygen -t ed25519 -f ~/.ssh/srvx -N ""
  2. Подними туннель — сервис слушает только loopback, публичного порта нет. 
    ssh -N -L 8765:localhost:8765 srvx-tunnel@<host> -i ~/.ssh/srvx
  3. Подключи MCP к своему агенту — появятся два инструмента: srv_explore(task) (задача словами) и srv_explore_cmd(cmd) (одна команда, дословный вывод). 
    claude mcp add --transport http srv-explore http://localhost:8765/mcp   --header "Authorization: Bearer srvx_…"
  4. Или работай отсюда — вставь токен на вкладке account и спрашивай на вкладке explore, без MCP.

Принципы работы

ПринципКак сделано
Одноразовая песочницаагент поднимается под каждый прогон отдельным процессом непривилегированного пользователя и умирает вместе с ним
Файловая система только на чтениеProtectSystem=strict: запись возвращает read-only file system от ядра, а не отказ модели
Интернета нетегресс обрублен на уровне ядра; наружу открыт только API модели через прокси с доменным allowlist
Docker через проксине сокет, а socket-proxy с POST=0: ps, logs, inspect работают, рестарт и удаление получают 403
Базы под read-рольплагин создаёт отдельную роль без права записи и проверяет это пробой-нарушителем: если запись прошла — установка считается неудачной
Доступ выдаётся поштучнофайлы и логи есть всегда, остальное — только включённые администратором плагины; выключил — креды агенту не уезжают
