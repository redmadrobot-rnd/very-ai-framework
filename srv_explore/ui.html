srv-explore · readonly-эксплорер сервера

Спроси сервер словами и получи факты — не имея доступа к серверу.

На хосте живёт агент, который умеет только читать: файлы, логи, конфиги, код, контейнеры, содержимое баз. Ты присылаешь вопрос, он выполняет команды чтения и возвращает сырые факты — что запустил и что это показало. Изменить он ничего не может, и это не обещание модели, а свойство окружения, в которое он заперт.

Что умеет

  • читать файлы, конфиги, логи, journald
  • искать по коду на хосте
  • смотреть контейнеры: ps, logs, inspect
  • делать SELECT-запросы в подключённые базы
  • systemctl status, df, ps

Что не сможет

  • записать файл — ФС смонтирована только на чтение
  • изменить данные в базе — роль без прав записи
  • рестартнуть сервис или контейнер
  • получить root, перезагрузить хост
  • уйти в интернет — егресс обрублен ядром

Как начать

Нужен токен от администратора — он же регистрирует твой SSH-ключ.

  1. поднять туннель до хоста
  2. вставить токен во вкладке «Мой доступ»
  3. спрашивать здесь или подключить MCP к своему Claude Code

Почему это безопасно

Агенту не запрещают писать — ему нечем. Каждый способ что-то изменить закрыт на уровне ресурса, а не уговорами:

ПопыткаЧто произойдёт
записать файлядро вернёт read-only file system
INSERT / UPDATE / DROPбаза откажет: permission denied
рестарт контейнерапрокси Docker API отдаст 403
отправить данные наружуегресс закрыт, наружу только API модели
повысить праванепривилегированный пользователь, NoNewPrivileges

Каждый прогон и каждая выполненная команда попадают в историю — видно, что именно спрашивали и что агент делал.
